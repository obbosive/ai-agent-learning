## 一、今天完成了什么

今天在 Day 3 的 JSON 持久化基础上，完成了一个可以持续运行的命令行论文管理器：

```text
程序启动
→ 从 JSON 加载一次论文列表
→ 显示菜单
→ 根据用户选择调用不同函数
→ 查询或修改数据
→ 修改类操作保存 JSON
→ 再次显示菜单
→ 用户选择退出后结束程序
```

目前支持：

- 查看全部论文；
- 添加一篇论文；
- 把指定论文标记为已读；
- 对空标题和非整数年份进行输入校验；
- 对不存在的论文给出提示；
- 对无效菜单选项给出提示；
- 使用 `4` 和 `break` 主动退出程序。

## 二、程序的数据流

程序中的核心变量是：

```python
loaded_papers = load_papers()
```

它是从 JSON 文件读取到 Python 内存中的论文列表。程序运行期间，各个函数接收并操作同一个列表：

```text
papers.json
    ↓ load_papers()
loaded_papers（内存列表）
    ↓ 作为参数传入
show_papers / add_paper / mark_paper_as_read
    ↓ 修改类操作调用 save_papers()
papers.json
```

查询与修改的区别：

| 操作 | 是否修改内存 | 是否需要保存 JSON |
|---|---:|---:|
| 显示菜单 | 否 | 否 |
| 查看论文 | 否 | 否 |
| 添加论文 | 是 | 是 |
| 标记已读 | 是 | 是 |
| 无效菜单输入 | 否 | 否 |
| 退出程序 | 否 | 否 |

## 三、`.strip()` 与空输入校验

读取输入时使用：

```python
title = input("请输入论文标题：").strip()
```

`strip()` 会删除字符串首尾的空白字符。例如：

```python
"  ReAct  ".strip()  # "ReAct"
"    ".strip()       # ""
```

空字符串在布尔判断中相当于 `False`，所以可以写：

```python
if not title:
    print("标题不能为空！")
    return
```

这里的 `return` 立即结束当前函数，防止无效数据继续进入后续流程。

---

## 四、字符串转换为整数与 `ValueError`

`input()` 的返回值永远是字符串。年份需要显式转换：

```python
year = int(year_text)
```

如果输入 `abc`，`int("abc")` 无法完成转换，会产生：

```text
ValueError
```

因此使用精确异常捕获：

```python
try:
    year = int(year_text)
except ValueError:
    print("年份必须是整数，论文添加失败。")
    return
```

验证结果：输入标题 `BadYear`、年份 `abc` 时，程序没有崩溃，JSON 也没有新增 `BadYear`。

当前校验只保证年份是整数，还没有检查年份是否合理。因此 `123` 可以成功转换成整数，但不一定是合理的论文年份。这属于后续可以增加的“取值范围校验”。

## 五、添加论文的完整流程

添加功能的数据流是：

```text
输入标题
→ 去除首尾空格
→ 检查标题是否为空
→ 输入年份
→ 尝试转换为整数
→ 创建新字典
→ append 到内存列表
→ 保存整个列表到 JSON
```

新论文使用字典表示：

```python
new_paper = {
    "title": title,
    "year": year,
    "is_read": False,
}
```

新论文默认设置为未读。`append()` 只修改内存列表，随后必须调用：

```python
save_papers(papers)
```

才能把变化持久化到硬盘。

---

## 六、遍历列表并修改其中的字典

标记已读时使用：

```python
for paper in papers:
    if paper["title"] == title:
        paper["is_read"] = True
```

循环中的 `paper` 指向列表里原来的字典，不是完全独立的复制品。因此修改字段后，`papers` 列表中的对应字典也会变化。

随后调用：

```python
save_papers(papers)
```

把内存变化写入 JSON。

---

## 七、查找成功后的 `return`

标记函数的核心结构是：

```python
for paper in papers:
    if paper["title"] == title:
        paper["is_read"] = True
        save_papers(papers)
        print("标记成功")
        return

print("没有找到该论文")
```

找到论文后使用 `return` 有两个作用：

1. 不再继续检查后面的论文；
2. 不会执行循环后面的“没有找到”提示。

“没有找到”必须放在整个循环结束之后，不能放在循环内部的 `else` 中。否则只要第一篇论文不匹配，就可能过早报告查找失败。

---

## 八、函数名与函数调用

今天再次遇到：

```python
mark_paper_as_read
```

这只是取得或提到函数本身，不会执行函数。

真正调用需要括号：

```python
mark_paper_as_read(loaded_papers)
```

同时，函数定义中要求的参数必须在调用时传入：

```python
def add_paper(papers):
    ...

add_paper(loaded_papers)
```

如果写成 `add_paper()`，会因为缺少必需参数而产生 `TypeError`。

---

## 九、交互式菜单与 `while True`

菜单需要在用户主动退出前持续运行：

```python
while True:
    show_menu()
    choice = input("请输入选择（1-4）：").strip()
```

`True` 是永久成立的条件，所以循环会持续执行。它不是失控的死循环，因为选项 `4` 中存在：

```python
break
```

`break` 结束的是当前整个循环；`return` 结束的是当前函数。二者作用范围不同。

`while 1:` 也可以运行，因为整数 `1` 转成布尔值是 `True`，但 `while True:` 表达目的更清楚。

## 十、菜单选择为什么与字符串比较

即使用户输入数字 `1`，`input()` 返回的仍然是字符串：

```python
choice = input(...)
```

因此应该判断：

```python
if choice == "1":
```

而不是：

```python
if choice == 1:
```

后者把字符串和整数比较，结果永远是 `False`。

---

## 十一、`if/elif/else` 菜单分发

菜单的控制流是：

```python
if choice == "1":
    show_papers(loaded_papers)
elif choice == "2":
    add_paper(loaded_papers)
elif choice == "3":
    mark_paper_as_read(loaded_papers)
elif choice == "4":
    print("退出程序！")
    break
else:
    print("无效选择，请重新输入。")
```

选项 `4` 必须单独判断。不能直接使用 `else` 退出，否则 `abc`、`9` 等所有无效输入也会被当成退出操作。

`else` 负责兜底处理所有没有被前面分支接受的输入。

---

## 十二、字符串内部的引号

今天曾把整段伪代码放进 `input()` 提示中，并在双引号字符串内部直接使用了 `"1"`、`"2"` 等双引号，导致：

```text
SyntaxError: invalid syntax
```

例如下面的结构有问题：

```python
input("请选择 "1" 或 "2"")
```

因为内部双引号会被 Python 当成外层字符串的结束位置。

最简单的解决方法是缩短提示：

```python
input("请输入选择（1-4）：")
```

也可以使用不同种类的引号或转义字符，但提示语首先应该做到简洁。

---

## 十三、Tab、空格与 Python 缩进

VS Code 中按下 `Tab` 后，编辑器通常会自动插入若干空格。本次检查发现文件中没有真正的 Tab 字符，使用的都是空格。

Python 对缩进的语法要求是：

```text
子代码块的缩进必须大于父代码块
同一个代码块的缩进必须保持一致
```

Python 并没有从语法上强制一级只能使用 4 个空格。因此函数体统一使用 8 个空格也可能运行，但社区规范推荐每深入一级增加 4 个空格。

今天发现 `save_papers()` 中曾有一行使用 5 个空格。这不一定立刻产生错误，但不利于维护。以后应逐步统一格式。

## 十五、今天出现的错误与根因

### 1. 输入提示产生 `SyntaxError`

原因：双引号字符串内部又直接使用双引号，外层字符串被提前结束。

### 2. `add_paper()` 没有传入参数

原因：函数定义要求 `papers`，调用时却使用空括号。

### 3. `mark_paper_as_read` 没有执行

原因：只写了函数名，忘记括号和参数。

### 4. 任意无效输入都会退出

原因：直接使用 `else` 执行退出，没有为选项 `4` 单独设置分支。

### 5. 年份 `123` 也能通过

原因：目前只验证了能否转换为整数，没有验证整数是否位于合理年份范围。

### 6. 认为按了 Tab 就一定使用标准缩进

原因：编辑器可能把 Tab 转成空格，而且代码块使用多少空格与是否符合 4 空格规范是两件事。

## 十六、个人学习提醒

1. `input()` 返回的一定是字符串，菜单选项应与 `"1"` 等字符串比较。
2. 用户输入后先 `strip()`，再判断是否为空。
3. `int()` 只能完成类型转换，不能证明数值在业务上合理。
4. 函数名后没有括号就不会调用函数。
5. 函数需要什么参数，调用时就要传入什么数据。
6. 修改字典字段只是修改内存，持久化仍需调用保存函数。
7. 找到目标后及时 `return`，避免继续循环或误报失败。
8. “没有找到”应在完整查找结束后输出。
9. `break` 结束循环，`return` 结束函数，不要混淆。
10. 退出选项应明确判断，无效输入交给最后的 `else`。
11. 不要把伪代码直接塞进用户提示语，提示应简洁。
12. 不要只验证程序能启动，要分别测试成功、失败和边界路径。
13. 不要用“粗心”概括所有错误，要区分语法、参数、调用和控制流问题。
