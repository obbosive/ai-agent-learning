## 二、PowerShell 是什么

PowerShell 是 Windows 中用来输入命令、操作文件以及启动其他程序的命令行工具。

可以使用以下方式打开：

```text
Win + R → 输入 powershell → 回车
```

打开后会看到类似下面的提示符：

```powershell
PS C:\Users\23854>
```

它可以拆成三部分理解：

- `PS`：当前使用的是 PowerShell。
- `C:\Users\23854`：当前所在目录。
- `>`：PowerShell 正在等待输入命令。

### 当前目录为什么重要

当前目录相当于命令行此刻“站着的位置”。使用相对路径时，PowerShell 会从这里开始寻找文件。

例如：

```powershell
cd .\Desktop\实习\ai-agent-learning
```

`cd` 是 change directory 的缩写，用来切换目录。

```powershell
cd ..
```

`..` 表示上一级目录。

### 个人注意事项

- 输入命令前先看提示符中的路径，确认自己在哪个目录。
- 出现“找不到路径”时，不要反复乱改命令，先检查当前目录和目标名称。
- 路径中有中文通常不是问题；如果含有空格，可以使用引号包起来。

## 三、Python 程序是怎样运行的

运行程序时使用过：

```powershell
python .\day01\hello.py
```

这条命令分为两部分：

- `python`：启动 Python 解释器，也就是负责读取并执行 Python 代码的软件。
- `.\day01\hello.py`：交给解释器运行的脚本文件路径。

因此，不能把整条命令笼统理解成“Python”。更准确的理解是：

```text
Python 解释器 + 要运行的 Python 文件
```

其中：

- `.` 表示当前目录。
- `\` 用于分隔 Windows 路径中的目录。
- `.py` 是 Python 源代码文件常用的扩展名。

### PATH 的作用

直接输入 `python` 后，Windows 能找到 Python 解释器，是因为安装目录被加入了 `PATH` 环境变量。

可以把 `PATH` 理解为一张“程序查找地址表”。如果没有正确配置，可能出现“无法识别 python 命令”之类的提示。

## 四、今天接触到的 Python 基础

### 1. 变量

变量可以理解为给一个值起名字：

```python
days = 7
hours_per_day = 3
```

这里：

- `days` 和 `hours_per_day` 是变量名。
- `=` 是赋值符号，表示把右边的值交给左边的变量名。
- 赋值不是在判断左右是否相等。

### 2. 字符串与整数

```python
goal = "学会独立编程"
days = 7
```

- 带引号的文本是字符串，例如 `"学会独立编程"`。
- 不带引号的数字 `7` 是整数，可以参与数学运算。
- 如果写成 `"7"`，它就是字符串，而不是整数。

### 3. 运算

```python
total_hours = hours_per_day * days
```

Python 会先读取右侧变量对应的值，计算 `3 * 7`，再把结果 `21` 赋给 `total_hours`。

### 4. 输出

```python
print("每周总学习时间：", total_hours)
```

`print()` 是 Python 提供的输出功能。括号中的多个内容用英文逗号分隔，程序会把它们输出到终端。

### Python 大致怎样执行文件

可以先建立一个当前阶段够用的模型：

1. Python 读取并检查代码是否符合语法规则。
2. 如果语法不成立，就报告错误，程序无法正常执行。
3. 语法能够解析后，程序通常从上到下依次执行。

以后还会逐步补充函数、分支、循环等会改变执行顺序的情况。

## 五、中文全角标点为什么会报错

今天遇到过这些字符相关错误：

- `U+FF0C`：中文全角逗号 `，`
- `U+FF09`：中文全角右括号 `）`
- `U+201C`：弯引号 `“`

Python 代码中的结构符号通常要使用英文半角字符：

```text
正确：,  (  )  "  '
易错：， （ ） “ ”
```

例如：

```python
# 正确
print("你好", goal)

# 错误示例
print（“你好”， goal）
```

### 为什么中文内容可以，中文标点却可能不行

字符串引号里面的中文只是程序需要保存或输出的数据；引号、括号和逗号则属于 Python 语法本身。Python 必须准确识别这些结构符号，中文输入法产生的全角标点与英文标点是不同的 Unicode 字符。

### 个人注意事项

- 写代码前查看右下角输入法状态，结构符号尽量在 `ENG` 状态输入。
- 中文可以写在字符串和注释里。
- 报错出现 `invalid character` 或 `U+xxxx` 时，优先检查中文标点和弯引号。
- 不要只盯着报错所在位置；真正错误有时位于它前面的引号或括号。
- 终端显示乱码与 Python 语法错误不是一回事：乱码可能只是字符编码或显示方式不一致。

## 六、Git 和 GitHub 不是同一个东西

### Git

Git 是安装在电脑上的版本管理工具。它可以：

- 记录代码的历史版本；
- 比较不同版本之间的变化；
- 在需要时查看或恢复历史内容；
- 支持多人协作中的版本管理。

### GitHub

GitHub 是网络上的代码托管与协作平台，可以保存远程 Git 仓库。

当前完成的是本地 Git 学习，还没有把仓库上传到 GitHub。即使不上网，Git 也能在本地工作。

## 七、Git 仓库、分支、提交与 HEAD

### 1. 初始化仓库

```powershell
git init
```

它会在当前文件夹中创建一个隐藏的 `.git` 目录。这个目录保存 Git 管理版本所需的信息。

它不会：

- 自动上传文件到网络；
- 自动创建 GitHub 仓库；
- 自动提交当前代码。

### 2. `master` 和 `main`

它们都只是分支名称。旧版本 Git 常用 `master` 作为默认分支名，现在许多项目使用 `main`。

把分支名改成 `main` 不会凭空改变代码内容，只是修改分支名称。

### 3. 分支

现阶段可以把分支理解成“指向某一串提交历史的可移动标签”。当前项目使用的是 `main` 分支。

### 4. HEAD

`HEAD` 表示当前所在的位置。现在可以理解为：当前正在 `main` 分支上工作，而 `main` 指向最新提交。

### 5. 提交哈希

每个提交都有一个用于识别它的编号，例如：

```text
d0a5c3e
526512a
```

`git log --oneline` 显示的是哈希的缩写。它们用于区分不同历史快照。

## 八、Git 最重要的三区模型

```text
工作区 ──git add──> 暂存区 ──git commit──> 本地仓库历史
```

### 1. 工作区

电脑上正在编辑、能够直接看到的文件。

修改并保存文件，只会先改变工作区。

### 2. 暂存区

用于准备“下一次提交具体要保存什么”。

```powershell
git add .\day01\hello.py
```

`git add` 会把执行这一刻的文件内容复制到暂存区。它不是持续同步，也不是最终提交。

### 3. 本地仓库

保存已经正式创建的历史提交。

```powershell
git commit -m "day1: update study hours"
```

`git commit` 保存的是暂存区内容，而不是直接保存工作区中的所有内容。

### 核心理解题

假设依次执行：

1. 把文件内容改成 `5`。
2. 执行 `git add`。
3. 再把工作区文件改成 `6`。
4. 不再执行 `git add`，直接 `git commit`。

那么：

| 位置 | 保存的内容 |
|---|---:|
| 工作区 | 6 |
| 暂存区 | 5 |
| 新提交 | 5 |

原因是 `git add` 是一次性的复制动作。执行后再修改工作区，不会自动改变暂存区。

提交之后，最新提交和暂存区都是 `5`，但工作区仍然是 `6`。此时 `git status` 会提示存在未暂存的修改，这不是报错。

### 为什么提交需要保持不变

提交的意义是保存当时的历史快照。如果旧提交会跟着工作区变化，那么历史就无法被可靠查看、比较和恢复，版本管理也就失去了意义。

日常使用中，如果代码后来变了，通常应当创建一个新提交，以此保留变化过程。

## 九、今天使用的 Git 命令

### 查看状态

```powershell
git status
```

作用：比较工作区、暂存区和当前提交之间的差异。

它是只读命令，不会修改文件或提交。

当前看到：

```text
On branch main
nothing to commit, working tree clean
```

含义是当前位于 `main` 分支，工作区没有未处理的修改，暂存区也没有等待提交的内容。

### 查看工作区中尚未暂存的变化

```powershell
git diff
```

它主要比较工作区与暂存区。没有输出通常表示两者没有差异，并不等于仓库中什么都没有。

### 将内容放入暂存区

```powershell
git add .\day01\hello.py
```

作用：更新暂存区中该文件的内容。

### 创建提交

```powershell
git commit -m "提交说明"
```

作用：把暂存区内容保存为一个新的历史提交。

`-m` 后面的文字是本次提交的说明，应尽量简洁描述修改内容。

### 查看精简提交历史

```powershell
git log --oneline
```

当前已有两次提交：

```text
526512a day1: update study hours
d0a5c3e day1:add first python program
```

上面的是较新的提交，下面的是更早的提交。

## 十、个人学习提醒

结合今天的学习过程，接下来需要特别注意：

1. **不要只复制命令。** 执行前先说出命令的对象、会修改什么、不会修改什么。
2. **先预测，再运行。** 运行代码或 Git 命令之前，先猜测输出和状态变化。
3. **区分报错与状态提示。** `modified`、`working tree clean` 都是状态信息，不是错误。
4. **遇到错误先读关键词。** 先找文件名、行号、错误类型，再检查相应位置。
5. **写代码时使用英文结构符号。** 尤其注意逗号、括号和引号。
6. **关注当前目录。** 很多命令失败不是命令本身错误，而是站错了目录。
7. **逐步减少对 AI 的依赖。** 可以让 AI 解释和提示，但每段代码都要能用自己的话说明。
8. **当前不需要觉得自己已经熟练。** 第一天的目标是建立正确模型；熟练来自后续重复使用。

今后的学习继续采用下面的顺序：

```text
先讲为什么 → 说明会改变什么 → 预测结果 → 自己操作 → 解释结果 → 写入每日笔记
```
